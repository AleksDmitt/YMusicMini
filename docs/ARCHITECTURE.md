# Краткая архитектура

Приложение WPF (.NET 10, Windows) использует `GlobalSystemMediaTransportControlsSessionManager` (GSMTC) для команд воспроизведения и сведений о треке, а Core Audio/NAudio — для громкости процесса.

## Основные подсистемы

- `MainWindow`: состояние капсулы, анимация, UI-команды, локальный расчёт прогресса и экспериментальный повтор.
- `MediaSessionService`: обнаружение/чтение медиасессии Windows, play/pause/next/previous/seek и повтор, если поставщик поддерживает.
- `VolumeService`: сессия звука конкретного процесса. Не следует менять громкость другого процесса при отсутствии сопоставления.
- `SettingsService` + `AppSettings`: JSON-настройки пользователя.
- `SurroundingThemeService`, `ForegroundThemeService`, `AccentPaletteService`: локальный выбор цветов.
- `DesktopVisibilityService`, `ForegroundVisibilityService`, `YandexWindowService`: работа поверх окон и скрытие.

## Повтор одной песни

Клиент Яндекс Музыки не обязательно выполняет API-команду GSMTC повтора. Текущий локальный вариант заблаговременно отправляет Previous/Seek и проверяет медиасессию; он не бесшовный. Два логических флага — запрос (`_repeatRequested`) и активность резервного повтора (`_localRepeatEnabled`). UI теперь синхронизирует `ToggleButton.IsChecked` и `CompactRepeatBadge.Visibility` по обоим флагам. Выключить повтор можно повторным нажатием кнопки.

## Кандидаты на будущий рефакторинг

- Вынести `RepeatController` из `MainWindow.xaml.cs` с интерфейсом для тестирования без реальной медиасессии.
- Разделить ViewModel и code-behind (MVVM) без одновременной переписи рабочего поведения.
- Исправить DPI-координаты и подключить автоматизированные UI-тесты на Windows.
- Разделить UI-тему, аппаратные API и платформенный слой; добавить полноценный журнал ошибок.

**Не оптимизировать без профилирования:** частота обновления, GDI/COM-вызовы и анимации чувствительны к особенностям Windows. Переход на MVVM и удаление сервисов должны проводиться маленькими проверяемыми шагами.
